## **1. Accessibility Working Group**

A working group that tests Trailhead and community project documentation with screen readers and other tools, and builds testing guides and best practices so Commons projects are accessible to everyone.

**Work performed at this sprint:**

- Set up a project Slack channel and trained on basic accessibility testing of image alt text, then moved on to more advanced testing tools and techniques
- Demoed how screen readers behave and sound
- Tested Trailhead and community project documentation, with feedback going to group leaders
- Set goals for future sprints, identified project leaders, and scheduled the first project team meeting

**Next Steps:**

- Meet in December
- Create testing guides and best practices
- Collaborate with other projects to support accessibility testing

**Resources:**

- [Accessible Salesforce Customizations (Trailhead)](https://trailhead.salesforce.com/content/learn/modules/accessible-salesforce-customizations)

## **2. AI For Nonprofits**

Community members building open source AI tools for nonprofits, including Slackbot skills, a Foundations Agent Advisor that helps small nonprofits decide on their first AI agent, and an AI data governance template.

**Work performed at this sprint:**

- Published and tested the first Nonprofit Slackbot skills (including donor meeting prep, who-needs-a-touch, log-gifts and Donor Thank You Notes) and created a new open source repo for nonprofit skills that works across Slackbot, Agentforce Coworker, Claude and others
- Built and tested the Foundations Agent Advisor, a tool-agnostic assistant that gives small nonprofits a verdict (Go, Go after prep, Different path or Not yet) on their first AI agent, plus a reusable AI data governance template
- Identified 20 potential Slackbot skills for NPSP and NPC, built a skills catalog, and connected the Slack and Salesforce development orgs for the Slack for Nonprofits Guide
- Explored reporting surface options outside of Slack, and added possible solutions to a spreadsheet to help build a screen flow that guides nonprofits to the best fit
- Documented lessons from testing, including how results vary by AI tool and that the discovery questions are where the value is

**Next Steps:**

- Projects continue under the AI for Nonprofits Membership group
- Create a screen flow for the reporting surface options
- Push skills to the GitHub project, then build, test and publish more skills

**Resources:**

- Project GitHub repository: [SF-community-skills](https://github.com/SFDO-Community-Sprints/SF-community-skills)

**Team leads:** Jana Walker and Katie Loescher

**Team members:** Denise Lee, Rama Goli, Renada Dukalskis, Lucy Hansen, Cynthia Hill, Aaron Winters, Alexis Tatham, Sven Schinker, Lyndsay Neer, Jodi Stewart, Iva Mandic, Cheyne Gallagher, Dalila Boggs, Omega Letana, Angelica Masangcay, Ramadevi Goli, Ronit Jorgensen, Joey Rocha-Perez, Beatrice Chau, Carrie Tan, Gordon Lee, Jean Chang, Kris Rosas, Steven Jiang

## **3. Grants Content Kit**

A kit that helps nonprofits find, evaluate and apply for grants using Salesforce and AI, shaped by a survey on how grant seekers use AI tools alongside their CRM.

**Work performed at this sprint:**

- Reviewed the existing architecture and synthesized nonprofit survey responses on AI and CRM usage in grant seeking, identifying key adoption trends. Nonprofits show clear interest in ingesting grant opportunities directly into CRMs.
- Completed technical scoping and UI design for the Grant Application Setup Flow, a guided screen flow with three paths (New Funder, Known Funder and Renewal)
- Scoped Grantmakers Web Search and Data Cloud Ingestion to automate RFP discovery and ingest grantor profiles into Data Cloud
- Drafted specifications for the AI Funding Readiness Skill and "Food for LLM" framework to evaluate funding opportunities against scored organizational criteria
- Finalized the Grant Research Toolkit, with a 15-minute quick screen, a 90-minute deep research process, and standard LLM prompts

**Next Steps:**

- Create wireframes, data models, and technical specifications from this work
- Resolve open architectural decisions on task ownership for groups and queues, and data model neutrality across NPSP and NPC
- Update survey logic for future survey waves (add an exclusive "None" option and separate official AI policies from informal staff usage)
- Start development of the screen flow and schema updates in Salesforce scratch orgs and the GitHub repository

**Resources:**

- [Grants Content Kit on the App Exchange](https://appexchange.salesforce.com/appxListingDetail?listingId=84736170-ba5f-49f0-a88d-fa824454b953)

**Team lead:** Mary Crozier

## **5. Membership Essentials**

An open source app that helps membership-based organizations manage memberships, renewals and gift memberships in Salesforce.

**Work performed at this sprint:**

- Shared historic project context, made MVP decisions for complex transaction scenarios, and set up tools and environments
- Finished the August 2026 sprint work and moved it into the main version of the Membership Essentials app
- Fixed several membership processing problems: renewals made during a grace period now count toward the existing membership, new memberships get the right type (individual, household or corporate), and gift memberships are checked for complete recipient details
- Added a way to flag renewals and a new status for submissions that couldn't be fully imported
- Built a large set of automated tests so these scenarios keep working as the app changes

**Next Steps:**

- Review seven more changes, including saving billing addresses on new organization accounts, more reliable campaign tracking, and removing outdated parts of the app
- Evaluate Mesh Mesh and move things forward

**Resources:**

A community-maintained library of best practices and downloadable packages for Nonprofit Cloud, including guidance for fundraising and stakeholder management. The Stakeholder Management Guidance Review team consolidated into this project on-site. [144 people have worked on NPC Best Practices over the years; 9 contributed at this Sprint...WOW!!!]

**Work performed at this sprint:**

- Provisioned an org with the Fundraising Quick-Start (FQS), read through the Commons and FQS documentation, and found updated links for 5 use cases
- Wrote and edited Google docs with suggested changes to the Guidance pages (Stakeholder Management proposed page updates and the Fundraising Guidance Review)
- Compared the Stakeholder Management Accelerator with NPC best practices and the Winter '27 release, finding several overlaps
- Removed the managed package, since the Quick Start Accelerator covers up-to-date automation, and confirmed quick start details with a Salesforce Solution Engineer

## **7. Outcome Tracking (NEW)**

What are people doing in Salesforce, and have they achieved their project goals? This project explores an object system that lets teams at nonprofit and educational institutions track what they are doing, the measurable target for each task, and whether they reached it.

**Work performed at this sprint:**

- Brainstormed with Higher Ed and Nonprofit Cloud experts and documented a draft object structure, then started building it in an org
- Created a "Team Member" object that connects to Contact to indicate staff, student employees, tutors, mentors and counselors
- Evolved the design to a "Team Recurring" object for regular activities (including the month) and a "Team Specific" object for individual activities, which allows list views by month within teams and across colleges
- Reviewed the PMM module for ideas, then built a custom object structure for community college use

**Next Steps:**

- Update the Recurring object to add months
- Create the Specific object

**Project idea by:** Yacy Zand

**Team members:** Antisha Partee, John Thomson, Corey Snow, Yacy Zand
